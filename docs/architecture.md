# MoonVerity 架构说明

## 分层

1. `core`
   负责契约模型、规则执行、校验报告、数据画像和契约 diff。
2. `adapters`
   负责把 CSV / JSONL 统一转换成 `Map[String, String]` 行记录。
3. `cli`
   负责把核心能力组织成便于终端输出和测试的命令接口。
4. `cmd/main`
   负责读取参数、读文件、决定输出格式。

## 设计取舍

- V1 不直接接数据库和远程服务，先把本地文件校验做扎实。
- V1 契约文件固定为 JSON，减少 DSL 解析成本。
- 明确把 CLI 逻辑从入口剥离，保证测试覆盖到真正的输出行为。

## 后续扩展方向

- 增加更多规则类型，如正则、日期范围、复合依赖规则
- 增加更多输入源，如 TSV、Parquet、数据库导出文件
- 增加 HTML 报告或静态检查面板
- 增加更细粒度的机器可读报告结构
